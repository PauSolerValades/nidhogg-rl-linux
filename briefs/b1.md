# Worker B1 — round-boundary diff: find the fields that step when a round starts or ends

**Read-only.** Do not write to game memory. The behaviour test (writing candidates) is a later
step and is not yours.

## Why this exists

The training loop needs to know **when a round ends** without screenshots. A previous attempt
produced 2283 candidates because it matched *values* (any timer steps by one). This brief
replaces value-matching with **timing + direction**: a phase field must step exactly at the
boundary and come back, so it is the intersection of two opposite transitions.

## Ground truth you can rely on (do not re-derive)

* `nidstate.enter_ready(i)` → READY screen; `nidstate.enter_match_v2(i)` → a verified live match.
* The push-based state file: `n.track(pid, tick=…)` + `n.state(pid)` gives `tick` at 60 Hz, so you
  can timestamp every dump.
* `n.memory_many(pid, [(base, size, path), …])` dumps many regions in ONE round trip (~1.2 s for
  all of rw memory, ~1.1 GB).
* `nidstate.regions(pid, min_size=1 << 20)` → the rw regions worth dumping.

## The forfeit recipe (exact — every detail below cost a session)

```
Escape                     # pause menu
sleep 1.5
Down  (hold=0.12)          # a plain press gets swallowed; hold ~120 ms
sleep 0.6
Down  (hold=0.12)          # now on FORFEIT
sleep 0.6
Return                     # dialog: "YELLOW FORFEITS?"
sleep 1.2
Right                      # the cursor starts on **NO** — this is the trap
Return                     # round ends, ORANGE "winner" screen
sleep 2.0
Return                     # continue → READY
```

Verify each step with `n.grab(i, path)` + a frame check; do not assume a key landed.

## What to produce

A candidate set of **u32 slots that step exactly at the boundary, in both directions.**

```
D0   live round              (dump)
t0   n.state(pid).tick        (timestamp)
-- forfeit --                (winner screen, confirmed by frame)
D1   winner screen           (dump)
-- continue --
D2a  READY                   (dump)
D2b  READY, 2 s later        (dump — excludes anything that drifts while idle)
-- start the next round --
D3   live round              (dump)
```

Keep a slot only if:

```
v(D0) != v(D1)          # changes at the boundary
v(D1) == v(D2a) == v(D2b)   # constant while the phase is stable
v(D2a) != v(D3)         # changes again at the next boundary
```

Then, if more than ~200 candidates survive, add a **third** boundary and intersect — do not
loosen the rule. Report the count at each stage.

**Required bookkeeping:** each dump's path and its region base go into `results/b1_layout.jsonl`
(a byte offset is meaningless without its base — this repository has been burned by that).
Dumps are large: write them under `/tmp/b1_<n>/` and delete them when the diff is done.

## Traps

* **Never press `d`/`a` repeatedly in a match**: walking into the goal *ends the round* and
  destroys the measurement (it happened; the round ended mid-test).
* Roles swap and records reallocate every round. This brief does not need to know which record is
  the player, so do not try to identify anyone.
* `pkill -x Nidhogg.exe` is forbidden: another lane's instance may be running.
* Your farm and display are set in the environment. Use `n.start_ids([0])` / `n.stop_id(0)` only.
* If a candidate's region is a huge reservation (hundreds of MB of zeros), say so — don't
  exclude it silently.

## Deliverable

`results/b1.json`:

```json
{"ok": true,
 "dumps": {"D0": 0, "D1": 1, "D2a": 2, "D2b": 3, "D3": 4},
 "counts": {"raw_changed_at_boundary": 0, "after_idle_stability": 0, "after_second_boundary": 0},
 "candidates": [{"base": "0x…", "offset": "0x…", "addr": "0x…", "vals": [0,1,0,0,1]}],
 "regions": {"0x…": 12},
 "dead_ends": []}
```

Final message: 8 lines max — the counts, the top candidate clusters, and anything that smelled
wrong. A clean negative with counts is a full result.
